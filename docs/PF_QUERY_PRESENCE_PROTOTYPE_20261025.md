# Query-Presence-Aware：机制原型与可行性边界

项目：TTA-RMOT。此阶段在六组完整实验结束之后开展，不是第七组正式方法，
不改变六组指标、预测、checkpoint或超参数。没有额外源训练、目标GT监督、外部语义教师。

## 六组结果支持什么

最优点估计Identity HOTA8.8179（+0.5999），但其视频聚类95%区间包含0，AUROC下降，
Empty FP增加10,421。Hybrid HOTA8.3213，未超过Identity；相对较强单模块的AssA上升
伴随DetRe下降，不显示所需互补。Rank只增加0.0253HOTA并消耗105,971次更新。
因此值得保留真实召回正向观测，但现有模块没有解决查询存在性和稳定语义排序。

## 与Rank/Identity本质不同的可检验问题

Rank保持同一query内冻结源排序；Identity使同一物理ID的条件特征跨帧一致。
两者均可能在完全不匹配的query-video上持续更新。相同分数的稳定性不是独立语言监督。

本原型只询问：给定相同候选框、运动和当前/过去图像，原模型的响应中是否存在
超出加性视觉/语言边际偏置的交互成分？使用同一个严格冻结的FlexHook做四次原始decode：

```text
J = S(V,Q) - S(V,Q0) - S(V0,Q) + S(V0,Q0)
```

`S`为原二分类margin；`Q0="person"`是一般类别参考，不是假负查询；`V0`为原多尺度
backbone特征的零值参考，不是标注为空的图像。四分支保持候选集合、物理ID、框、位置、
运动和帧历史完全相同，只读取被请求的过去/当前特征。没有合成新的跨域测试集。

若`S=a(V)+b(Q)+c(V,Q)`（给定同一geometry），则J严格消去a、b的加性项，
剩下参考中心化交互。因而它提供一个原Rank/Identity没有单独测量的无标签**诊断量**，
可证伪“只是加性边际分数变化”的解释；它不自动给出可靠的语义学习方向。
冻结视觉/text编码复用，解码仍为原模型；代价是每次四次decode，不能宣称免费。

## 为什么现在不能拿J训练presence

- 稳定错误匹配也可有正J；原模型的伪相关交互会保留。
- 特征零值是分布外参考，位置/运动先验仍在，不能解释成真实“场景没有目标”。
- 一般类别文本不是可交换的负样本；不同表达难度/语义粒度并不校准。
- 没有候选只说明当前MOT未观测到候选；J≤0或稳定负源margin均不证明查询为空。
- 时间持续性来自同一图像流/物理ID，也不能独立证实衣着/动作描述。

因此本轮**没有找到已验证、独立于原模型错误匹配的语义presence学习信号**。
这不是对所有未来无标签信号的不可能性证明，而是此原型的可识别性边界。
不把J>0、物理ID一致或过去硬负标签作为正/负伪标签，也不另加一个没有依据的loss。

## 实际代码行为

`flex_tta/adaptation/presence_evidence.py`实现四分支交互及有界因果历史。
注册沿用3次过去观测/最大gap2的规则仅用于报告“暂时交互支持”，没有根据Dance GT调门限。
可以同时支持零个、一个或多个候选；此支持不是语义正例。

每一步返回`presence_status=UNKNOWN`、`optimizer_update_allowed=False`、
`prediction_override=None`。UNKNOWN不会被偷偷转为空目标硬标签；本原型保留原冻结预测作为
fallback（其集合允许空或多个），不覆盖正式预测。这是明确保留未识别能力，不是声称
全部UNKNOWN就是成功的presence分类器。每episode清空历史，禁止未来帧或回放旧episode状态。

六个针对性CPU检查覆盖加性偏置消除、稳定正交互仍UNKNOWN、空/多目标、因果顺序和
episode重置、过期/负交互、零交互不等于absence。只验证这些研究必要性质，不做防御性覆盖扩张。

## 研究决策

保留这个可运行的交互审计原型，**不把它升级为已验证的Query-Presence-Aware TTA**。
要研发真正的适应，必须先找到能约束语义正确性的新无标签信号及可证伪假设，且不能依赖
Dance GT presence比例、强制top1/目标数、外部教师或错误硬标签。没有这种信号就停止叠加损失。
本阶段完成原型及小规模验证后停止，不自动启动新一轮完整GPU实验，等待用户明确指令。
